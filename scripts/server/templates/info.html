Info & Glossary

Every term used on this dashboard, in one place. Research & reporting only — nothing here places orders.

This site backtests ETF allocation strategies on cached Interactive Brokers price data, validates them for overfitting and luck, and supports a monthly manual rebalance workflow. The site never places orders — all trades are entered by hand in IB Gateway.

Performance metrics

Total Return
End value ÷ start value − 1, over the whole backtest, after transaction costs.
CAGR (Compound Annual Growth Rate)
The constant yearly return that would produce the same total return over the same period. Lets strategies with different backtest lengths be compared.
Volatility
Annualised standard deviation of returns. Higher = bumpier ride. Computed from the portfolio's periodic returns and scaled to a year.
Sharpe Ratio
Average excess return per unit of volatility (annualised). The main risk-adjusted score. Rule of thumb: < 0.5 weak · 0.5–1 decent · > 1 good — but see Deflated Sharpe below for why a raw Sharpe from many trials overstates skill.
Max Drawdown
Largest peak-to-trough loss over the backtest, in %. The worst-case "how much would I have been down if I'd bought the top".
Omega Ratio
Probability-weighted gains ÷ probability-weighted losses around a 0% threshold. Unlike Sharpe it uses the whole return distribution, so fat tails and skew count. > 1 means gains outweigh losses.
Returns to Turnover
Total return divided by total traded volume. Low values mean the strategy churns a lot for each unit of return — costs and slippage will hurt it in practice.
Transaction Costs
Backtests charge 7.5 basis points (0.075%) per trade. "Total Costs" is the cumulative £ spent on trading.
Rebalance Frequency
How often target weights are recomputed and traded — monthly here, matching the manual IB workflow.
Rolling metrics
Sharpe/volatility/drawdown recomputed in a moving window (on the strategy page) to show whether performance was steady or came from one lucky stretch.

Validation battery (per strategy)

Verdict PASS WARN FAIL
Worst outcome across the battery below. FAIL means at least one test says the result is likely luck or overfit; WARN means borderline.
DSR (Deflated Sharpe Ratio)
Probability that the true Sharpe is > 0 after correcting for how many strategies were tried (N trials), backtest length, skew, and fat tails. Trying 200 variants guarantees some high raw Sharpes by chance; DSR deflates for that. PASS ≥ 0.95 · WARN ≥ 0.90 · below = FAIL.
N trials
How many strategy variants were effectively tried when producing a result — the denominator of every multiple-testing correction. Estimated per family from the number of sibling definitions.
MinBTL (Minimum Backtest Length)
Given N trials, the shortest backtest that could distinguish skill from luck. If the actual history is shorter than MinBTL, even a great-looking result is statistically meaningless.
CPCV (Combinatorial Purged Cross-Validation)
Splits history into groups, trains/tests on many train–test combinations, and checks the strategy still works out-of-sample in most of them. "Purged" = overlapping observations near the split are dropped so information can't leak across.
Embargo / Purge
A buffer (in days) around each CPCV test window that is excluded from training, preventing leakage from serially-correlated returns.
Block Bootstrap
Resamples the return series in multi-month blocks (preserving autocorrelation) thousands of times to build a distribution of Sharpe ratios. If 0 sits well inside that distribution, the observed Sharpe isn't distinguishable from noise.
k-fold consistency
Fraction of time-folds in which the strategy beat its benchmark. 5/5 folds positive is robust; 2/5 suggests the average was carried by one period.

Overfitting & data snooping (family-wide)

Overfitting
When a strategy's parameters are tuned (deliberately or not) to the past's noise instead of a persistent effect. It looks great in-sample and fails live.
PBO (Probability of Backtest Overfitting)
Across a family of parameter variants: the probability that the variant chosen as best in-sample underperforms the median out-of-sample. PASS < 0.30 · WARN < 0.50 · above = FAIL.
CSCV (Combinatorially Symmetric Cross-Validation)
The engine behind PBO: split history into S subsets, use every half/half combination as in-sample vs out-of-sample, and see how often the in-sample winner flops out-of-sample.
Parameter sweep / family
All variants of one strategy class across a parameter grid (e.g. momentum with top-1/2/3, 1/3/6-month lookbacks). PBO is only meaningful across such a family — sibling variants of the same idea.
Group PBO (composed families)
Vol-target variants of the same base strategy (e.g. hrp_15vol / hrp_30vol) are backtested separately, so their return matrix is reassembled from saved results and CSCV is run on the group (needs ≥ 4 usable siblings).
SPA (Superior Predictive Ability) / Reality Check
The library-wide go/no-go: tests whether the best strategy in the whole collection genuinely beats the equal-weight benchmark after accounting for having searched across all of them. A small p-value (< 0.05) means the outperformance survives the snooping correction.
Walk-forward analysis
Re-fits/evaluates the strategy on a rolling train→test schedule, mimicking live deployment through time rather than one big in-sample fit.
Stress test / Scenario removal
Performance measured inside known crisis windows, and leave-one-crisis-out reruns: drop each crisis from the data and re-run to check the result doesn't depend on a single episode.

Strategy taxonomy

Allocation strategy
Computes target weights across a list of assets (e.g. HRP, risk parity, momentum top-N). Defined in strategy_definitions/allocations/.
Overlay strategy
Transforms the weights of an underlying strategy — e.g. volatility targeting scales exposure up/down; a gold safe-haven overlay shifts weight to gold in stress. Defined in overlays/.
Composed strategy
An allocation wrapped in one or more overlays, as a single definition in composed/. Naming: hrp_15vol = HRP base + 15% vol-target overlay.
Portfolio / meta-portfolio
A fixed- or dynamic-weight blend of other strategies (portfolios/) — diversification across strategies rather than assets.
Vol targeting (15vol / 30vol / 8vol)
Overlay that scales positions so realised portfolio volatility tracks the target (15%, 30%, 8% annualised). Cuts exposure in turbulent markets, adds it in calm ones.
HRP (Hierarchical Risk Parity)
Clusters assets by correlation (ward/average linkage variants), then splits risk down the cluster tree. Robust alternative to mean-variance — no expected-return estimates needed.
Risk parity
Weights assets so each contributes equally to portfolio risk (inverse-volatility in its simplest form).
Minimum variance / Maximum diversification
Optimisers that minimise portfolio volatility, or maximise the diversification ratio (weighted average vol ÷ portfolio vol), respectively.
Momentum top-N
Ranks assets by trailing return over a lookback (1/3/6/12 months) and holds the top N. "Dual momentum" adds an absolute filter: hold cash/bonds when even the winners are falling.
Trend following
Long assets above their moving average / positive trailing return, out (or defensive) otherwise. trend_signal_mvo/_rp feed trend signals into MVO or risk-parity weighting.
Carry
Tilts toward assets with higher expected "holding yield" (e.g. futures curve shape, dividend/coupon proxies) — cross_asset_carry variants.
Mean reversion / Long-term reversal
Buys recent losers expecting a bounce — short-horizon (days–weeks) for mean reversion, multi-year for reversal.
Seasonality (Halloween, presidential cycle)
Calendar effects: "sell in May" (Halloween effect) and the US presidential-term-year pattern.
PAA (Protective Asset Allocation)
Momentum-based risk-on/risk-off: the fraction of assets in downtrends sets how much moves to the safe asset (the last asset in its definition list).
Universe groups (universe:all, universe:bond, …)
Named asset groups in strategy_definitions/universe.json (equity, bond, commodity, europe_equity, em_equity, all). Definitions reference groups instead of hand-copied asset lists, so new assets propagate automatically.

Pipeline & data

Backtest
scripts/run_backtest.py: monthly-rebalanced simulation on cached daily ETF prices (GBP, £10k start, 7.5 bps costs, 252-day lookback warm-up). Results land in results/strategies/<key>/.
Price cache
Parquet files under data/cache/, fetched from IB Gateway when available. Offline, the backtester falls back to the newest cached file per symbol (with a STALE warning); symbols with no cache are skipped.
Run jobs API
POST /api/run/<strategy_key> launches backtest → validation → overfitting as background subprocesses (fresh code each run); poll GET /api/run/status/<job_id> for state and final metrics. Used by build agents; never places orders.
strategies_index.json
Master index of backtested strategies powering this dashboard. The strategy list is the union of the index and the on-disk result folders, so a partial run can't hide results.
Live Risk
Current IB positions (read-only) mapped against strategy weights — a monitoring view for the manual monthly rebalance. Orders are always entered by hand in IB Gateway.
